# 特效计划：分组激活（提线收紧）

## 1. 设计意图

墨缇丝「演奏」不发动效果，而是点亮一个分组。要让玩家看到：**每点亮一组，就有一根线被绷紧、牵回到她身上**；四组齐备＝四根线全部连上，小睦才被拉回场上。这是「提线的本我」最直白的可视化，也预先解释了复活。

- 触发/对象：`PuppeteerFormManager.ActivateGroups(...)` 首次点亮某分组时触发一次性；常驻状态由分组位掩码驱动。
- 对象：睦的演奏区——四组各 3 条**斜切平行四边形行**（真实形态：160×50、ItemScale 0.7、行距 49px、左右两列、右侧镜像）；
  分组角标（`ActivatedGroupBadge_<和弦>`）在该组第一行外端。
- 角色意象来源：墨缇丝＝提线木偶；四个和弦分组＝四根弦／四根线。
- 不改变的：激活规则、幂等性、四组全亮触发复活的判定时刻。
- 用户已表达的偏好：要求「激活后要有视觉表现（非解冻）」。

### 1.5 与真实形态的对齐（事实）

- 激活某组 = **该组的 3 条行同时点亮**（描边 + 底色提亮），不是只亮一枚角标。
- 角标在行的外端；提线从「该组第一行的外端」拉向角色命中框中心，因此左列走右下、右列走左下。
- 一次性扫光沿该组 3 条行自上而下掠过（右下组则为自下而上，保持「从点击处出发」）。

- **四组全亮时**：四条 `thread_persist` 同时闪一次（0.38→0.85→0.30，0.25s），作为「小睦被拉回来」的前置提示；复活特效不属本计划。
- **循环**：否（一次性 + 常驻）。
- **基类**：`Node2D`（纯表现）。
- **挂点**：`NPerformArea` 下 `GroupActivationVfx_<和弦>`；行坐标取 `_items[i].Position` 实时值。

## 4. 验收标准（契约）

- [ ] 首次激活某组时 0.40s 内完成：三条行点亮 → 扫光掠过 → 线长出 → 环扩散 → 光点沿线到达角色
- [ ] 已激活的组再次「演奏」不重播一次性层，只有常驻线/行描边保持（幂等）
- [ ] 「点亮」覆盖该组**全部 3 条行**，且不误亮相邻组（C 与 D 同列仅隔 5px）
- [ ] 常驻线始终连接「该组角标」与「角色命中框中心」，演奏区重建后位置正确
- [ ] 线的颜色恒等于该和弦分组色（C/D/F/G），与槽位、卡面书签同源
- [ ] 四组全亮时四条线同步闪一次，**不**与复活动作抢拍（复活延后 ≥0.15s）
- [ ] 未激活的组无任何线/行描边亮起；解冻（复活）后所有线与行描边在 0.30s 内消失
- [ ] 同屏与冻结特效共存时，线在冰壳之上（z 序更高），可读
- [ ] 手柄/键鼠指向槽位时线不拦截鼠标（`MouseFilter = Ignore`）

## 5. 授权包络（契约）

| 参数 | 本计划基准 | 可调整范围 | 不可改变的约束 |
|---|---|---|---|
| LIFE（一次性） | 0.40s | ±40%（0.24–0.56s） | 不延迟激活/复活判定 |
| 各层显示尺寸 | 见 §3 | ±30% | 环仍以角标为圆心 |
| alpha 峰值 | 见 §3 | ±0.25（0–1 内） | 线在深色底上必须可见 |
| 旋转角度 | 星芒 8° | ±15° | 线的主轴不改变（角标→角色） |
| 装饰层（星芒/线结） | 见 §3 | 可增删 | 不影响主体（线）与节奏峰值 |

**不可改，改了要重新确认**：素材集合、主体形态（提线 + 点亮角标）、用途/触发与结算时刻、核心层数量（提线与环两层必留）。

## 7. 决策与默认值（不锁）

### 7.1 来源与归属

| 素材 | 归属校验 | 凭据 |
|---|---|---|
| whiteRing / star_322 / star_270_1 / glow_soft | 工程内 | `BangDreamInSpire/BangDreamInSpire/images/vfx/`（随仓库） |

### 7.2 决策记录

| 决定 | 值 | 依据 |
|---|---|---|
| 母题 | 提线 + 行点亮（不用音乐符号做主） | 「扫弦」方向（扫光 + 音符 + 星芒）作为备选；提线独占墨缇丝的意象，四线齐备直接预示复活 |
| 常驻 vs 一次性 | 一次性 + 常驻线 + 行描边 | [自定] 玩家需要随时看到「哪几组已亮」 |
| 线从角标起 | 角标 → 命中框中心 | [自定] 起点是玩家刚点的位置，终点是「她本人」，动作方向可读 |
| 四线闪一次 | 0.25s 同步闪光 | [自定] 与复活动作留 0.15s 间隔，避免抢拍 |

## 8. 假设与风险（不锁）

- 四根线从四角汇向角色，在演奏区与角色重叠处可能显得杂乱；若明显，常驻线 alpha 降到 0.30 并只画到命中框边缘（不进入角色胸腔）。
- 角色 `HitboxCenter` 锚点会随体型/缩放变化，实现时用命中框中心实时换算，不写死像素。
- 若后续希望「线随演奏摆动」，属包络外的形态变化，需重新确认。
