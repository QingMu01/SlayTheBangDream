# 特效创作工作流（用户协作版）

**第 0 步（强制）**：读 `docs/vfx-authoring.md` 与 `docs/vfx-preview-mechanism.md`。它们是实现方式的**唯一事实来源**；本文件只规定**与用户协作的流程与证据**，不重复实现规范。

> 用户确认想看到的效果与调整边界；agent 负责混合模式、曲线、基类等实现决策。
> 把需要用户判断的观感翻译成可见的选择，已有偏好和授权持续有效。

## 展示优于命名（软约束）

**默认尽量把挑中的资产画出来给用户看，而不是只报资产名。**

理由：本库素材名多为短名、数字名或**误导名**——实测 `T_VFX_SparklesF21` 不是散点闪光、
`base_glow` 不是圆形辉光、`star_04` 是个实心三角形。**用户看到名字根本无法判断**，
看图却是一秒的事。只报名字等于把判断成本推给用户。

### 关键决策点**必须**出图

| 时机 | 出什么图 | 用什么工具 |
|---|---|---|
| S1 给候选让用户挑 | 联络表（带编号徽标） | `render_contact_sheet` |
| 缩小到最终候选 | 1:1 素材预演图（染色、尺寸与混合近似） | `preview_candidates.py` |
| S4 计划确认 | 同上，**附在摘要里** | `preview_candidates.py` |
| S5 逐层验证 | 每轮内部目视取证；用户参与判断时展示抽帧/1:1 裁切 | `record.sh` + 本地裁切 |
| 交付 | mp4（主）+ gif（便于直看） | `record.sh --gif` |

其余场合（比如逐层推进的中间轮次）不必每轮都出图，避免刷屏；
视觉形态/素材选择必须给图；时长、用途、授权等非视觉选择用明确描述即可，不强制编造配图。

### 怎么做

- 图内**带编号**，正文用编号对应名称，不要只贴一张图让用户猜哪张是哪张。
- 用 Markdown 内联：`![说明](<路径>)`。路径含空格要用尖括号。
- 图之外**仍要给一句形态描述**（"四角星芒，纯白，中心实心"），
  这样即使图没渲染出来，信息也不丢。

### 降级

确实无法出图时（工具不可用、环境限制），**至少给一句形态描述**——
不能只给名字。说明为什么没能出图，别静默省略。

## 铁律：闸门之前不修改正式特效资源

**在 `check_gate.py` 返回 0 之前，禁止**：

- 创建/修改任何 `.cs`、`.tscn`、`.tres`、`.gdshader`
- 在 `BangDreamInSpire/` 下新建目录或复制素材
- 运行 `dotnet build` 或任何导入命令
- 声称"我先搭个骨架再问"

批准前允许：读文件、调用 MCP 检索/预览工具；在 `<repo>/.vfx_staging/` 内导出真实素材、把来源凭据写进计划文件（**不产出 `SOURCES.md`**）、写计划与预演 JSON、运行现有预演脚本生成图片。这些准备操作不得写入正式资源目录或修改资产库；预演规格、图片和来源凭据都是准备产物，不视为实现代码。

不要把此限制套用于用户明确要求的 skill 文档/工具维护；本轮维护授权不等于批准任何特效计划。

```
python .agents/skills/vfx-authoring/scripts/check_gate.py --plan <plan.md>
# exit 0 → 放行；exit 1 → 未批准；exit 2 → 计划已改，批准失效
```

## 阶段状态机

| 阶段 | 做什么 | 产出 | 完成判据 |
|---|---|---|---|
| **S0** 意图捕获 | 提取用途、角色/卡牌、已有参考和偏好，判定新增/改造；缺用途时先确认用途 | 一句话意图 + 已知约束 | 素材侦察有方向，用户没被甩技术问题 |
| **S1** 素材侦察 | 查 MCP，拿真实候选 | 候选表（uuid/名称/特征）+ **联络表图** | 库内候选有真实 uuid，且**已把图给用户看过** |
| **S2** 结构化访谈 | **漏斗式一次一问**，无轮次上限，按收敛条件停 | 决策记录 | 类型 + 风格 + 关键观感已定（或用户主动叫停） |
| **S2.5** 素材预演 | 按染色、显示尺寸、混合与压黑参数预演；必要时合成静态峰值；过图层角色↔特征检查 | 预演图 + 检查结果 + 近似限制 | 已检查形态及叠加风险，不将预演当作引擎动态证据 |
| **S3** 计划落盘 | 写 `plan.md` | `plan.md`（`status: draft`） | 含真实素材来源、**预演图**、层结构、验收标准和授权调整范围 |
| **S4** 确认闸门 | ⛔ 停下等用户，**摘要里内联预演图** | `status: approved` + 批准人 | 用户**明确**说可以 |
| **S5** 实现与自检 | **逐层**写码 → **逐层**录帧 → 交付（交付附 mp4/gif） | 场景+脚本+mp4/gif（是否含贴图由本体归属校验决定） | 每层增量录帧看过，完整播放已按正常速度观看，非仅编译过 |

**S0 先理解用途，S1 给宽泛视觉参考，S2 再收敛风格，S2.5 前按已定用途/主色精筛素材。** 用户已有参考或偏好时直接利用，不为满足步骤重复提问；素材选择题须先有图。

## S0 意图捕获

开场直接说明将进入访谈，避免用户以为你会立刻动手：

> 这个特效我打算先跟你确认几件事再动手，**只问缺失的观感信息，每次一个问题**。
> 我会先翻一遍你的素材库，拿几张实际候选给你挑——你不用懂术语，看图选就行。
> 随时可以说"够了，直接出计划"。

先从用户描述、卡牌本地化及现有实现提取触发、对象、角色意象、参考和禁用元素；不要新增玩法或改结算。必要时仅补问用途，再进入 S1。创作方向与参考拆解见 [references/creative-direction.md](references/creative-direction.md)。

同时判定分支：

| 分支 | 触发 | 差异 |
|---|---|---|
| **新增** | 不存在该类名 | 走完整 S1–S5 |
| **改造** | 已有 VFX 脚本要调观感/时长/换素材 | 素材已定可跳 S1；S2 收敛到改哪里；S3 列变更项、保留约束和调整范围 |

## S1 素材侦察（Polaris MCP）

工具用法与选材判据见 [references/asset-selection.md](references/asset-selection.md)。要点：

1. `library_info` 看库规模与已有标签（首次连接）。
2. **`get_selection_spec`（或 resource `polaris://spec/selection.json`）取权威取值**——
   facet / 角色 / 组织方式 / 阈值 / 可检索维度都由 Polaris 核心注册表生成，**不要凭记忆猜取值**。
3. `search_assets` 用**结构化过滤或主体级选材**定位，不要只靠关键词：
   - 资产级：`tags:["VFX"]`、`kinds`、`alpha`、`fill_ratio`、**`holes`（`[0,0]` = 只要实心的）**、
     **`components`（`[1,1]` = 只要单颗主体）**、`dark_outline`、`glow_range`、`colors`+`color_min_ratio`、
     `width/height`、`sub_types`；
   - 主体级（会给到**具体帧**）：`role`（8 个用途角色）+ `mode`（`scout` 找灵感 / `strict` 精筛）
     + `facets`（受控形态事实）+ `dimensions`（维度区间）+ `target_px`/`tint`/`blend`（按使用条件排序）
     + `unknown_features`（未知证据三档）。
   两者都是 SQL 级过滤，`total` 即真实命中数——**比关键词可靠得多**，因为库内素材名多为短名/数字名。
4. **读候选的 `risks` / `required_review`**：未知证据不会被当作通过，标了待复核的必须目视；
   `effective_constraints` 说明了本次角色默认风险与候选池是否被截断。
5. `render_contact_sheet`（≤256 个，`cell_size` 128–256）**批量粗筛**。**它只用于淘汰明显不合适的**，不能用来下最终结论——联络表的分辨率不足以判断形状细节。
6. 缩小到少数候选后，用 `render_asset_preview`（`max_size` 可到 **2048**）逐个看高清。**这一步不能跳。**
7. 图集/序列帧用 `get_asset_group_preview` 拿帧结构——**这是设 `hframes`/`vframes` 的唯一依据，不要目测**。
8. 选定后 `export_assets` 导出到 `.vfx_staging/`（不要污染仓库，也不要在库内改名）。
9. **入库前必须做本体归属校验**——判断导出的到底是不是本体素材：

   ```
   python .agents/skills/vfx-authoring/scripts/check_asset_origin.py <导出目录>
   ```

   - `BODY`：**不要复制进工程**，场景里直接按输出的本体 uid + `path` 引用；
   - `LOCAL`：按原流程重命名为语义名、复制进 `images/vfx/<特效名>/`，再 `--headless --import` 生成 `.import`/uid；
   - `REVIEW`：与本体某张图同尺寸且感知哈希接近（疑似改绘），人工判定后再选前两条之一。

**候选表必须落到 uuid**。计划里写"某个闪光贴图"等于没做侦察。

**给用户看候选时必须附图**（见「展示优于命名」）：把 `render_contact_sheet` 的联络表内联出来，
正文用**编号**对应名称，不要只丢一串资产名。用户看不懂 `base_glow` / `star_04` 这种名字，
但一眼就能挑出想要的形状。

**当前分支需要 S1 且 Polaris 不可用时停止素材侦察。** 用已暴露的 Polaris 只读工具检测连接；不要把缺少资源列表接口误判为断连。若工具明确返回 `server is disconnected`：

1. **立即中断本次流程**——不进入 S2，不用本地素材凑合，不"先做着看看"。
2. 向用户报告实际错误、已确认原因与仍未确认的项、可执行的修复步骤；不得把猜测写成根因。
3. 恢复后用只读工具确认连接，再从 S1 继续，无需重复已答访谈。

理由：S1 的全部价值是拿到**真实库内候选**。没有候选池，S2 的素材选择题（Q7）无法进行，
不得伪造 uuid 来填补候选。已定工程内素材的改造分支仍按 S0 跳过 S1，记录实际来源。
**宁可停下，也不要产出一份看起来完整、实则凭空捏造的计划。**

## S2 结构化访谈（漏斗式，一次一问）

题库见 [references/question-bank.md](references/question-bank.md)，翻译表见 [references/translation-tables.md](references/translation-tables.md)。

**核心：一次只问一个问题，从大方向逐层收窄到具体内容。**

| 层 | 问什么 | 为什么在这一层 |
|---|---|---|
| **L1 大方向** | 用途 / 触发时机 | 决定类型模板，并决定后面**问哪些、跳过哪些** |
| **L2 风格与观感** | 画风 → 主色 → 亮度质感 | 决定层结构与参数倾向 |
| **L3 运动与节奏** | 运动方式 → 节奏 / 时长 | 决定曲线与 `LIFE` |
| **L4 具体内容** | 素材取向（**带图**）→ 脏元素 → 附加结构 | 到这一步用户才有语境看图选 |
| **L5 边界（按需）** | 循环 / 同屏数量 | 只有对应类型才问 |

规则：

- **一次只问一个问题。** 不要在同一轮抛多个问题——用户会答得草率，后面的答案还会受前面干扰。
- **不设轮次上限**，但必须做到两件事：
  - 每题都带**进度提示**（「第 N 问 / 预计共约 M 问」），让用户知道还有多久；
  - 满足**收敛条件**就立即停（见 question-bank.md「什么时候停」），不要为了问而问。
- **每题给 2–4 个具体选项（不含逃生口）**，附一句"这个选项看起来是什么样"。
- **每题必须带逃生口**："看不懂 / 你决定"。选了就走推荐默认值，**不再追问**。
- **用户已经说过的不要再问**——他常会顺口答了后面的题，记下来、跳过，并在计划里注明来源。
- **素材题必须附图**（内联联络表 / 预演图，图内带编号），不能只给资产名。见「展示优于命名」。
- 用户**连续两题选"你决定"**就整体收敛，其余走默认值并在计划里标 `[默认值]`。

**顺序不能倒。** 一上来就问"用哪张图"会让不懂特效的用户无从答起；
而先定了"用途 + 画风 + 亮度"，他到素材题时自然就知道该挑哪种形状。

**典型路径约 8 问**（L1 一题 + L2 三题 + L3 两题 + L4 两三题），用户多说"你决定"会更少。

## S2.5 素材预演（1:1，强制）

**这一步是硬要求，不是建议。** 控制台读数和联络表都看不出素材的形状缺陷——
必须按预计染色、尺寸与混合参数预演素材形态。**该脚本是静态近似，最终叠加、shader 和动态效果以 S5 引擎录制为准。**

### 为什么强制

实测数据：一次命中特效共发现 4 个缺陷，其中 **3 个是素材缺陷**，全部**在批准阶段看不见**，
直到五层写完、录帧之后才暴露，导致**三次重开闸门**：

| 素材 | 缺陷 | 160px 联络表 | 256px 联络表 | 1:1 预演 |
|---|---|---|---|---|
| `base_glow` | 不规则拱形（不是圆形辉光），尾段成"鬼影" | ✗ | ✗ | **✓** |
| `flash_v2` | 中心八边形扇贝花纹；自带黄绿描边 | ✗ | ✗ | **✓** |
| `star_04` | 实心三角形（不是"闪光核心"） | ✗ | ✗ | **✓** |

**1:1 预演能拦下全部三个。** 跳过它，就要用三次返工来换。

### 怎么做

```powershell
python .agents/skills/vfx-authoring/scripts/preview_candidates.py `
  --spec .vfx_staging/preview_spec.json --out .vfx_staging/out/preview.png
```

规格文件写预计参数；完整字段与近似限制见 [references/preview-spec.md](references/preview-spec.md)：

```json
{
  "background": "#4B4B4B",
  "items": [
    { "path": ".vfx_staging/export/star1/star1.png",
      "label": "burst_outer", "role": "burst", "blend": "alpha_add",
      "tint": "#6BCCFF", "display": 328, "alpha": 1.0 },
    { "path": ".vfx_staging/export/dot/dot.png",
      "label": "glow", "role": "glow", "blend": "alpha_add",
      "tint": "#6BCCFF", "display": 365, "alpha": 0.55 }
  ]
}
```

- `tint` 必须填**场景里真正用的颜色**（含提白变体）。染色是乘算：带色贴图染冷色会发暗发脏。
- `display` 填该层在屏幕上占的**最大像素尺寸**（简单尺度曲线可取 `max(s0,s1) × 384px`；有过冲时取实际峰值）。
- 明确 `blend`：`alpha`、`alpha_add` 或 `crush_add`；压黑时填实际 `black_point`、`softness`、`intensity`。旧规格缺省 `alpha` 会告警，不能据此确认发光效果。
- 需要检查叠加时填写 `composition` 与各项 `x/y/z`，生成未加标记的静态合成图；它不代替动态录制。
- 脚本打印内容框与放大倍数，放大 > 3× 告警。洞数是阈值分析线索，艺术上有意留空或通过核心层填补时可说明理由；不得仅因数字排除合适素材。
- 深色描边来自 MCP 特征和目视，不声称脚本自动检测了描边。

### 角色 ↔ 特征否决表

**读特征时不要"看一眼"，要按角色判定。** 同一个字段在不同角色下含义相反。
角色集合与阈值以 `get_selection_spec` 为准（核心注册表生成）；脚本口径对照见
[references/selection-contract.md](references/selection-contract.md)。

| 图层角色（核心 id） | `洞 > 0` | `深色描边 > 0` | `填充率` | 放大 > 3× |
|---|---|---|---|---|
| 爆散 / 光斑 / 闪光核心（`burst`/`glow`/`flash`） | 默认否决；有意留空/核心补洞可说明并合成核对 | **否决**（染色后残留异色边） | — | 告警 |
| 圆环 / 框线（`ring`） | ✓ 预期 | **否决** | 应偏低 | 告警 |
| 烟雾 / 云（`smoke`） | 告警（可能是空洞） | 否决 | — | 告警 |
| 火花 / 粒子（`spark`）、碎片（`debris`） | ✓ 预期 | 否决 | `spark` 应偏高 | **否决**（粒子小图放大必糊） |
| 拖尾（`trail`） | ✓ 预期 | 否决 | 天然偏低，不据此否决 | 告警 |

**图集/序列帧不是角色**：旧写法 `role: atlas` 已弃用——图集是**组织方式**
（`representation=grid_animation|packed_atlas|image_sequence`），用途仍要按上表选一个角色。
仍用 `atlas` 时预演脚本会打弃用告警并按 `spark` 判据继续。

**任何角色下 `深色描边 > 0` 都要否决或说明理由**——单色 `modulate` 无法独立改掉素材的边缘颜色；
保留有色描边、采用原色或有意使用暗边时写明理由，以预演目视判断。
**黑底不透明素材的描边判据不适用**（边缘发暗是衰减而非描边），特征会显示"不适用"——
"不适用"不等于"没有描边"，也不等于"通过"。

### 产物去向

预演图和否决检查结果**写进 `plan.md` 的「素材预演」一节，并在 S4 摘要里给用户看**。
用户确认的是已展示的素材形态与拟定观感；预演的静态近似限制须同时说明。

## S3 计划落盘

用 [references/plan-template.md](references/plan-template.md) 的模板写 `<repo>/.vfx_staging/plans/<slug>.md`。

计划必须包含：

1. **决策来源**：每个决定来自第几问（漏斗式访谈一次一问），以及顺口提到、未单独提问的项。
2. **素材清单**：库内 uuid/名称，或已定工程/新绘来源的路径、hash/作者；另附语义名、用途、原始尺寸，以及本体归属校验（`check_asset_origin.py`）的判定结果。来源凭据只写在计划文件里，不伪造 uuid。
3. **素材预演**：S2.5 的 1:1 预演图路径 + 否决表逐项检查结果（`洞`/`深色描边`/`放大倍数`）。
4. **层结构表**：每层的贴图、混合模式、起止时间、尺度、alpha、旋转、z 序。
5. **尺寸归一化**：各贴图原生尺寸不一，必须先归一到统一参考框（约定 **384px**），
   由场景节点 `scale` 承担；脚本里的 `s0`/`s1` 是相对倍数。见 [references/csharp-recipes.md](references/csharp-recipes.md)。
6. **基类决策**：默认 `Node2D`；只有"飞过去且命中驱动玩法"才 `NBangDreamFlyingVfx`（见 `docs/vfx-authoring.md` §2）。
7. **验收标准**：可判定的句子，如"第 0.10s 出现白色闪光，0.34s 前完全消失"。
8. **`[默认值]` 标注**：凡是没问过用户就定的，逐条标出来。
9. **假设与风险**：如"素材为黑底 JPG，需压黑处理"、"`star1` 原始 72px，放大 4.8× 可能模糊"。
10. **交付物清单**：**不含任何 git 相关内容**（见 S5.3）。
11. **创作方向**：角色/卡牌意象、视觉主次、参考保留点与禁用元素；已有明确方向时无需增加访谈。
12. **授权调整范围**：允许调整的参数、单位、上下界及不可改变的观感/玩法约束；未列出的变更不在授权内。

`t0/t1` 一律为归一化时间；层表同时列 `开始秒=t0×LIFE`、`结束秒=t1×LIFE`。叙述和验收用秒，帧号用 `秒×fps`，不要直接把 t1 当秒数。

## S4 确认闸门

1. 把计划**摘要**讲给用户（不要贴整份文件让他读），重点说：会看到什么、多长、用哪些素材、哪些是默认值。
   **同时给出 S2.5 的 1:1 预演图**——用户确认的是已展示的素材形态与拟定观感；预演的静态近似限制须同时说明。
2. **停下**。不要在同一轮里继续做任何实现动作。
3. 只有用户**明确**说"可以 / 开始 / 没问题 / 就这么做"才算批准。以下**不算**：嗯、还行、你觉得呢、先这样吧。
4. 批准后：

```
python .agents/skills/vfx-authoring/scripts/check_gate.py --plan <plan.md> \
  --approve --approved-by "<用户原话或标识>"
python .agents/skills/vfx-authoring/scripts/check_gate.py --plan <plan.md>   # 必须 exit 0
```

5. 原批准计划保持不变（包括授权范围），指纹仍校验全部正文。S5 可在**用户批准的调整范围**内调参，将实际值、原因、证据、验收结论写入独立 `tuning-log.md`，交付同时报告；日志不扩大授权，`check_gate.py` 不自动校验实现值是否在范围内，agent 须逐项核对。
   - 未声明范围时以计划值为准；未列参数、超范围、换素材、改变主体形态/用途/命中结算时刻，先 `--reopen`、更新计划并重新确认。
   - 已经明确授权的范围内不重复请求许可。修复使实现回到批准计划的代码错误不需要重新批准。
6. **`--approved-by` 必须填用户的原话。** 闸门会把它记进 frontmatter 供事后审计——
   不填就是"自批准"，无法区分"用户真批准了"和"agent 自己放行了"。

## S5 实现与自检

实现细节见 [references/csharp-recipes.md](references/csharp-recipes.md)。

### S5.0 前置

1. 复制素材到 `BangDreamInSpire/BangDreamInSpire/images/vfx/<特效名>/`，重命名为**语义化文件名**。
2. `--headless --import` 生成 `.import` 与 uid。**不要手写 uid。**
3. 场景里按计划中**从底到顶**的层序摆好所需节点（例如 `glow → ring → burst_outer → burst_core → flash → sparks`；不需要的层省略），
   每层 `scale` 按 384px 参考框归一（见 [references/csharp-recipes.md](references/csharp-recipes.md) §6.1）。

### S5.1 逐层验证（核心，不得跳过）

**脚本里的 `Layers` 表一轮只加一层。** 每层走一遍同一个循环：

| 步骤 | 动作 |
|---|---|
| 1 | 在 `Layers` 表里**只添这一层**（前面的层保持不动） |
| 2 | `dotnet build` |
| 3 | `record.sh` 录**一个循环**（`--quit-after` ≈ `LIFE × 60 + 余量`） |
| 4 | **抽帧目视 + 1:1 原始像素**（缩放图会掩盖细节） |
| 5 | 对比**上一轮**的录制：新增的瑕疵必来自本轮这一层 |
| 6 | 通过才进下一层；**不通过就停在这一层修，绝不带着已知瑕疵往上叠** |

观察点（每轮都看）：

- 该层的**出现时刻、消失时刻**是否与计划的 `t0`/`t1` 一致；
- 素材轮廓是否与 S2.5 的 1:1 预演图一致；混合/压黑差异以引擎图为准（**这一步能立刻看出素材的形状缺陷**）；
- 加法混合下与已有层的**叠加**是否过曝、是否出现新伪影。

**为什么必须逐层**：五层一起上时，录帧看到瑕疵**无法归因是哪一层**。
本次为此额外花了两步（本地渲染贴图 + 1:1 中心放大）才定位到"外层花纹"和"火花朝向"。
底色层单独录一次，就能当场看出拱形鬼影之类的素材缺陷。

**每轮的录制目录都要留着**，最后一轮结束后可以横向对比，
判断某个现象是哪一层引入的、以及是不是层间交互造成的。

> 只有 1–2 层的简单特效可跳过逐层，直接进 S5.2；但仍必须先单录第 1 层。

### S5.2 全量核对

1. `dotnet build` 通过。
2. **录完整循环**（覆盖 ≥2 个 `LIFE`）：

```
bash .agents/skills/vfx-authoring/scripts/record.sh \
  -s "res://BangDreamInSpire/scenes/vfx/<场景>.tscn" -n 130 --gif
```

3. **机器校验**——一次性淡出效果可加 `--fail-on-freeze`；持续/常驻效果不将冻结自动判失败，仍核对实际预期。`verify_frames.py` 会告警"疑似未淡出"（占比长时间冻结），
   这是 alpha 曲线写反的典型症状之一，不是确定诊断：

```
python .agents/skills/vfx-authoring/scripts/verify_frames.py <rec 目录> --fps 60 --fail-on-freeze
```

4. **1:1 目视**关键帧（峰值 / 各层消失时刻 / 尾段）。
5. **按正常速度观看完整播放**，检查主次、动作方向、命中峰值及收尾；抽帧只补充定位，不能代替节奏判断。不能播放时明确动态验收未完成，不从截图推断通过。
6. **逐条核对计划的验收标准及授权调整范围**，记录实际秒数和最终参数。反馈转译与正常速度验收见 [references/creative-direction.md](references/creative-direction.md)。冻结检测是异常线索；持续/循环效果按预期状态判断，不能机械要求淡出。
7. 不满意时先定位最主要的问题，每轮优先调整一个假设并与上一版本对照；新参数不得越过授权范围。

**编译通过不等于完成。** 必须抽帧目视，且对每条验收标准给出可核对的结论。

### S5.3 接入确认与交付

1. **确认特效真的被接入**——搜类名与场景路径，只命中定义文件即为孤儿（`docs/vfx-authoring.md` §2.1）。
   注意 `WithHitFx` 解析的是游戏本体资源，改字符串到不了 mod。
   **本 demo 若不接入，必须在计划与交付说明里明确声明。**
2. 交付：场景 + 脚本 +（**仅当校验判定为非本体素材时**）贴图与 `.import` + `tuning-log.md`（有调参时）+ mp4/gif。**不产出 `README.md` / `SOURCES.md`。**
3. 交付时**附上 mp4 与 gif**（见「展示优于命名」）——不要让用户只拿到一个文件名。
4. **交付物不涉及 git。** 全程**不执行任何 git 操作**
   （`add` / `commit` / `stash` / `branch` / `checkout` / `restore` 都不要碰），
   交付说明里**也不附** git 状态、`diff`、`diff --stat`、提交记录或分支信息。
   版本控制由用户自己决定何时提交、提交什么。
   **交付物只包含特效本身的文件**：
   脚本、场景、（非本体素材的）贴图与 `.import`、调参日志（如有）、mp4/gif。

## 反模式

- ❌ 跳过 S1 直接问技术问题
- ❌ 需要 S1 且 MCP 断连时伪造候选或静默改来源；应停止侦察并报告实际错误
- ❌ **跳过 S2.5 直接写计划**——只用联络表/缩略图决定素材，不做 1:1 预演
- ❌ 用 `render_contact_sheet` 的结果下最终结论（它只用于粗筛淘汰）
- ❌ **让用户在几项之间做选择时只给资产名不给图**——用户看不懂库内短名
- ❌ 一次写完所有层再录帧（瑕疵无法归因）
- ❌ 带着已知瑕疵往上层叠（应停在该层修完再继续）
- ❌ **一次抛多个问题**（应一次一问，从大方向逐层收窄）
- ❌ **不告知进度地无限追问**（每题须带「第 N 问 / 预计共约 M 问」，满足收敛条件即停）
- ❌ 重复问用户已经说过的内容（他常会顺口答了后面的题）
- ❌ `check_gate.py` 未通过就建工程/写脚本
- ❌ `--approve` 不带 `--approved-by`（等于自批准）
- ❌ 替用户决定风格而不标注 `[默认值]`
- ❌ 按文件名或缩略图判断素材内容
- ❌ 用 `find_similar_assets` 选这类素材（dHash 对暗底柔形 VFX 失效）
- ❌ 素材未落实真实来源，或为工程/新绘素材伪造 uuid
- ❌ 从资产库导出的素材没过本体归属校验就复制进工程（本体素材应直接引用）
- ❌ **对仓库执行 git 操作**（`add`/`commit`/`stash`/分支），或在交付说明里附 git 状态与 diff
- ❌ 只跑通代码就宣布完成
