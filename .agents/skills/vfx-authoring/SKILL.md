# 特效创作工作流

模型负责设计与实现，用户只审方向与最终观感。

## 1. 前置与原则

先读 `docs/vfx-authoring.md` 与 `docs/vfx-preview-mechanism.md`。实现规范以这两份文档为准。

- 先确定主体运动、峰值和收尾，再选素材。
- 只保留服务主体、节奏或角色意象的层。
- 优先调整运动与节奏，不用白闪、粒子或曝光掩盖问题。
- 构建、无头运行和帧校验只证明技术正确；最终观感以真实战斗原速录像为准。
- 用户建议明显损害效果时，给出理由与更好的对比方案；用户坚持则照办。

## 2. 授权与确认

| 模式 | 适用情况 | 确认方式 |
|---|---|---|
| `review` | 新设计、用户有明确偏好或方向有分歧 | 最多确认一次质量目标或动态草样 |
| `preauthorized` | 用户明确授权模型决定 | 不暂停，交付实战视频 |
| `guided` | 用户明确要求通过提问澄清 | 按 [question-bank](references/question-bank.md) 集中提问 |

方向明确时直接执行。需要确认时，只锁主体与角色意象、视觉峰值、禁止元素和实战可读性，模板见 [plan-template](references/plan-template.md)。

素材、层数、混合、曲线和参数是实现决策，可为质量自由调整；用户明确指定的除外。`preauthorized` 与边界清楚的局部改造无需运行 `check_gate.py`。

## 3. 流程

| 步骤 | 动作 | 完成判据 |
|---|---|---|
| 1. 质量目标 | 确定主体、参考、禁区、实战尺寸与同屏压力 | 一句话说清玩家第一眼看到什么 |
| 2. 动态草样 | 用简单形状或现成素材验证运动与节奏 | 原速播放的主体动作与峰值成立 |
| 3. 美术化 | 按草样选择或制作素材 | 每层有作用，无已知素材缺陷 |
| 4. 实现 | 编写场景与脚本，完成技术验证 | 构建、运行、触发与生命周期正确 |
| 5. 实战验收 | 原速对照、减法审查与返修 | 实战表现满足质量目标 |

改造可复用素材并缩短第 3 步；纯技术修复可省略计划。观感改造不得跳过第 5 步。

### 3.1 质量目标

从本地化、调用代码、角色设定和同类特效读取触发、对象、结算时刻、实际尺寸、单次/多次语义及重叠情况；能从仓库确认的不要问用户。

复杂或全新设计在 `.scratch/vfx/plans/<slug>.md` 记录：主体、角色意象、参考与禁区、峰值对应的玩法时刻、遮挡与同屏约束。参数起点按需查 [translation-tables](references/translation-tables.md)。

### 3.2 动态草样

默认做一个主方向；只有主体或运动存在真实分歧时才加对照。

- 在 `.scratch/vfx/` 用基础几何、工程贴图或粗素材搭原型，不改正式资源。
- 通常输出不超过 2 秒的 mp4，按实际尺寸和代表性背景原速观看。简单改造可直接录正式场景粗版。
- 先写动作句，再确定蓄势、峰值、停留与收尾；蓄势不是必需项。
- 静态合成只辅助造型、颜色与构图。素材预演按 [preview-spec](references/preview-spec.md) 使用。

需要用户确认时在此一次收敛。方向不对就更换主体或运动，不靠堆装饰修补。

### 3.3 美术化

素材可来自 Polaris、工程、本体、程序化形状/shader 或新绘。没有合适库存素材时更换来源或制作。

使用 Polaris 时按 [asset-selection](references/asset-selection.md) 检索、目视和导出，并遵守：

1. 图集结构以 `get_asset_group_preview` 为准，名称和描述不能替代目视。
2. 保留真实 uuid 与 `_provenance.json`，不得伪造来源。
3. 复制前运行 `check_asset_origin.py`：`BODY` 引用本体，`LOCAL` 才复制，`REVIEW` 人工判定。
4. 关键主体、大图、放大超过 3×、疑似黑洞或异色描边时做 1:1 核对；有意的形态特征结合合成结果判断。

### 3.4 实现

实现细节见 [csharp-recipes](references/csharp-recipes.md) 和主规范。

- 先实现主体运动，再加必要装饰。
- 改图后运行 `--headless --import` 再构建；资源 uid 由引擎生成。
- 简单效果可整体录制；复杂交互或定位伪影时才用 `stage.sh` 做单层/增量对比。
- 构建与无头运行必须通过；一次性效果按需用 `verify_frames.py` 检查残留、冻结和结束状态。
- 每轮调参聚焦一个主要问题，只记录重要决策与最终结论。

### 3.5 实战验收

- **单场景录像**：检查生命周期、素材形状、伪影和精确时刻。
- **实战原速录像**：按实际尺寸连同角色、敌人、背景和 UI 检查主体、角色意象、峰值、收尾与遮挡；连打、群攻或常驻效果还要检查重叠或持续表现。

先原速完整观看，再按需慢放或抽帧。与旧版、参考或本体同类效果同尺寸对照；删除不损害主体、节奏或角色意象的层。反馈排查见 [creative-direction](references/creative-direction.md)。

无法取得实战录像时，明确标注「实战观感未验收」。

## 4. 交付

- 提供场景、脚本、必要贴图与 `.import`，确认真实调用点；`WithHitFx` 限制见主规范。
- 提供原速实战 mp4；gif、关键帧和逐层对比按需附加。
- 简述实际观感、与旧版的差异、验收范围和未完成项。
- 不生成 per-effect `README.md` / `SOURCES.md`。实际触发点、最终层结构与素材来源回写 `docs/mechanic-authoring.md`；通用技术坑回写 `docs/vfx-authoring.md`。
