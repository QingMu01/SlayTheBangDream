# 特效创作工作流（设计师主导版）

**定位**：模型是设计师，用户是审稿人。

- **模型定**：艺术方向、核心意象、层结构、素材取舍、参数、实现与验证手段。
- **用户定**：要不要这个效果、方向对不对、验收边界（"太吵/太软/不像她"）。用户不需要懂术语，也不需要替模型做技术决策。

**为什么这样分**：这套流程保留的是**证据链**（预演、录帧、归属校验、契约锁），去掉的是**审批层**（逐题请示、措辞级锁死）。

## 0. 先读实现规范

进任何流程前读 `docs/vfx-authoring.md` 与 `docs/vfx-preview-mechanism.md`。它们是实现方式的唯一事实来源；本文件只规定**协作方式与证据标准**。

## 1. 设计权与三条"给发挥"的规则

在授权包络内，**方案由模型定，不需要为每个决定找依据**。同时：

1. **表现力优先于合规感。** 不要因为"这样更保险"就选四平八稳的方案——纯白爆散、单层闪光、不加旋转，通常不是最好的设计，只是最不容易被挑错的设计。合规成本由本流程的脚本承担，不由你的创意承担。
2. **偏离默认值只需说明理由，不需要重新批准。** 计划里标 `[自定]` 并写一句为什么即可；只有契约块（素材/层表/验收/包络）变更才需要用户再确认。
3. **认为用户给的方向明显更差时，先反对。** 给出理由 + 一个更好的备选方案，用图或录屏对比；用户坚持则照办。不要用讨好式执行换取"用户满意"——那是在替用户做差设计。

## 2. 授权模式（S0 定一次，贯穿全程）

| 模式 | 何时用 | 谁定方向 | 确认点 |
|---|---|---|---|
| **review**（默认） | 用户有自己的想法，或想先看方案 | 模型提案，用户选 | S4 一次确认 |
| **preauthorized** | 用户说"你决定 / 全权交给你 / 发挥你的全力" | 模型 | 无；交付看 mp4/gif |
| **guided** | 用户说"我说不清，你问我吧" | 用户（3 屏选择） | S4 一次确认 |

- 模式只看用户怎么说，不看用户角色。用户给了一句明确指令（"五线谱环加上旋转"）就属于 review 的强输入，**不要**把它变成 8 个问题的访谈。
- **preauthorized 不等于跳过证据**：预演、逐层录帧、验收、交付附件一个都不能少。它跳过的只是"请示"。
- 用户中途改变主意（"等等，我想换个方向"）→ 改 `mode`，契约变了就 `--reopen` 重走确认；契约没变就直接改。

## 3. 阶段状态机

| 阶段 | 动作 | 判据 |
|---|---|---|
| **S0** | 提取用途、对象、已有偏好、授权模式；判定新增/改造 | 知道要做什么、谁拍板 |
| **S1** | MCP 检索真实候选 + 看图 | 候选有真 uuid、已看过高清 |
| **S2** | **给 2–3 个设计提案**（每个带静态合成预演图） | 用户选定/混合/否决一个方向 |
| **S2.5** | 按风险做 1:1 预演核对 | 形状关键层已看图、否决项有结论 |
| **S3** | 计划落盘（契约块 + 说明） | 契约块四节齐全 |
| **S4** | 一次确认（仅 review/guided） | 用户明确说可以 |
| **S5** | 逐层实现 → 全量核对 → 交付 | 每层有录制证据，交付带 mp4/gif |

改造类（已有 VFX 调观感）：素材已定可跳 S1；S2 收敛到"改哪里、改成什么"；其余相同。

## 4. 展示优于命名

库内素材名多为短名/数字名/**误导名**（实测 `T_VFX_SparklesF21` 不是散点、`base_glow` 不是圆形辉光、`star_04` 是实心三角形）。**只报名字等于把判断成本推给用户。**

- 决策点必须出图：S1 候选用 `render_contact_sheet`（带编号）；S2 提案用静态合成图；S5 交付用 mp4 + gif。
- 图内带编号，正文用编号对应名称，**并附一句形态描述**（"四角星芒，纯白，中心实心"），图挂了信息也不丢。
- Markdown 内联：`![说明](<路径>)`。真出不了图时说明原因 + 给形态描述，不许静默省略。

## 5. S0 意图与权限

从用户描述、卡牌本地化、现有实现里提取：触发、对象、角色意象、参考、禁用元素。**不改玩法与结算。**

只补问缺失且会改变方向的项，一次一个；能从代码/本地化读出来的不要问。开场一句话说明模式：

> 我按"我先出方案、你挑"的方式做。会先翻素材库、给你 2–3 个带图的方案，你选一个我就写计划确认。

## 6. S1 素材侦察（Polaris MCP）

工具用法与判据见 [references/asset-selection.md](references/asset-selection.md)。

1. `library_info` 看规模与已有标签；`get_selection_spec`（或 `polaris://spec/selection.json`）取权威取值——**facet/角色/阈值不要凭记忆猜**。
2. `search_assets` 用**结构化过滤**而不是关键词：`tags:["VFX"]`、`alpha`、`fill_ratio`、`holes`（`[0,0]`=实心）、`components`（`[1,1]`=单颗主体）、`dark_outline`、`glow_range`、`colors`+`color_min_ratio`、`width/height`。主体级：`role` + `mode` + `facets` + `dimensions` + `target_px`/`tint`/`blend` + `unknown_features`。
3. 读 `risks` / `required_review`：未知证据不算通过，标了待复核的必须目视。
4. `render_contact_sheet`（≤256 个）**只用来粗筛淘汰**，分辨率不够下结论；缩小到少数候选后 `render_asset_preview`（`max_size` 到 2048）逐个看高清，**这步不能跳**。
5. 图集/序列帧用 `get_asset_group_preview` 拿帧结构——**这是设 `hframes`/`vframes` 的唯一依据**。
6. `export_assets` 到 `.scratch/vfx/`（自动带 `_provenance.json`）；不在库内改名/删除。
7. **入库前跑本体归属校验**：`python .agents/skills/vfx-authoring/scripts/check_asset_origin.py <导出目录>`
   - `BODY`：**不复制**，场景里直接引本体 uid + path；
   - `LOCAL`：重命名为语义名，复制进 `images/vfx/<特效名>/`；
   - `REVIEW`：疑似改绘，人眼判定后二选一。
8. **候选必须落到 uuid 或真实路径**；"某个闪光贴图"等于没做侦察。

**MCP 明确返回 `server is disconnected` 时**：立即停止侦察，报告实际错误与修复步骤，不用本地素材凑合、不伪造 uuid。恢复后从 S1 继续，不用重问已答内容。

## 7. S2 设计提案（替代访谈）

**默认不做访谈，做提案。** 让用户在 8 个抽象选项里选，不如直接给 3 张图。

### 7.1 提案长什么样

2–3 个**完整方案**，不是一个方案的三个变体。每个包含：

| 项 | 内容 |
|---|---|
| 名字 | 一句能看出立意的短名（"封闭的音符"，不是"方案A"） |
| 意象 | 一句话说清它和角色/卡牌的关联，以及主体是什么 |
| 图 | **静态合成预演图**（`preview_candidates.py` 的 `composition`）——按预计染色、尺寸、混合拼出整帧 |
| 结构 | 2–4 行说明：几层、谁主谁次、时长、节奏峰值 |
| 代价 | 需要的素材数、放大倍数风险、实现复杂度 |

- 三个方向必须有**真实差异**（例如：几何刚硬 vs 有机流动 vs 节奏驱动），不是同一方案的亮度差异。
- 节奏/运动本身就是方案关键时（如"脉冲跟拍"），允许在 `.scratch/vfx/` 搭**只含图层的原型场景**录 ≤2s mp4——正式资源仍然不碰。
- 提案图必须内联给用户看；文字只说"会看到什么"，不要罗列参数。

### 7.2 用户怎么回

任一种都属于收敛：选一个 / "A 的环 + B 的节奏" / "都不对，我要 X" / "你决定"。

- 选/混合 → 按选择推进；混合时把冲突点（谁做主体、时长取谁的）自己判断，记录在计划的"决策与默认值"里。
- "都不对" → 问一句他最不想要什么，然后换方向重出提案；不要在同一方向上加装饰。
- "你决定" → 按推荐方向走，标 `[自定]`。

### 7.3 guided 模式（少数情况）

用户明确要求被提问时，才走 [references/question-bank.md](references/question-bank.md) 的**三屏**：`第一屏 观感`（画风 + 主色 + 亮度，各给候选图/色条）→ `第二屏 节奏`（运动 + 时长）→ `第三屏 内容`（素材取向，带联络表 + 要不要烟/环）。每屏 2–3 题，每题有"你决定"逃生口，**不要**拆成一次一问的十几轮。

## 8. S2.5 素材预演核对（按风险触发）

**为什么存在**：命中类特效的多数缺陷是素材缺陷，联络表分辨率看不见，1:1 预演能提前拦下。跳过它就要用返工来换。

| 触发条件 | 要求 |
|---|---|
| burst / flash / glow / ring 图层且显示尺寸 ≥ 256px | **强制** 1:1 预演（`preview_candidates.py --spec ... --out ...`） |
| spark / debris / trail 且显示 < 256px | 联络表高清预览足够；放大 > 3× 仍要核对 |
| 所有图层的"深色描边" | 任一角色下花色描边都要否决或说明理由（单色 modulate 改不掉边缘颜色） |

预演规格写进 `plan.md` 的「素材预演」一节（不进契约块），**在 S4 摘要里给用户看**，同时说明它是静态近似、动态以 S5 录制为准。

否决表（按角色看特征，**同一字段在不同角色下含义相反**）：

| 角色 | 洞 > 0 | 深色描边 | 填充率 | 放大 > 3× |
|---|---|---|---|---|
| burst / glow / flash | 默认否决（有意留空需合成核对） | 否决 | — | 告警 |
| ring | 预期 | 否决 | 应偏低 | 告警 |
| smoke | 告警 | 否决 | — | 告警 |
| spark / debris | 预期 | 否决 | spark 应偏高 | 否决 |
| trail | 预期 | 否决 | 不据此否决 | 告警 |

受控取值与阈值以 `get_selection_spec` 为准；口径对照见 [references/selection-contract.md](references/selection-contract.md)。黑底不透明素材的描边判据不适用（"不适用"≠通过）。

## 9. S3 计划与契约块

写 `<repo>/.scratch/vfx/plans/<slug>.md`，模板见 [references/plan-template.md](references/plan-template.md)。

**闸门只锁契约块**（`<!-- gate:begin -->` 与 `<!-- gate:end -->` 之间），四节：

| 节 | 为什么锁 |
|---|---|
| 素材清单 | 换素材=换效果，必须重新确认 |
| 层结构 | 层表决定观感承诺 |
| 验收标准 | 这是"做完了没有"的判据 |
| 授权包络 | 用户授权模型调参的边界 |

块外随便改：设计意图、决策与默认值、假设与风险、预演图路径、调参记录——措辞、补充说明、错别字都不会让批准失效。

**授权包络给默认值**（不填就用这套），让绝大多数调参不需要重新批准：

| 项 | 默认允许 |
|---|---|
| LIFE | ±40% |
| 各层显示尺寸 | ±30% |
| alpha 峰值 | ±0.25（0–1 内） |
| 旋转角度 | ±15° |
| 装饰层（spark/smoke/trail）增删 | 允许，不影响主体 |
| **不可改** | 素材集合、主体形态、用途/触发与结算时刻、核心层数量 |

## 10. S4 一次确认

1. 讲摘要（不贴文件）：会看到什么、多长、用了哪些素材、哪些是 `[自定]`；**内联提案图/预演图**。
2. **停下**，等用户明确表态（"可以 / 开始 / 就这个"）。"嗯 / 还行 / 你看着办"不算批准。
3. 批准后写指纹：

```bash
python .agents/skills/vfx-authoring/scripts/check_gate.py --plan <plan.md> \
  --approve --approved-by "<用户原话>"
python .agents/skills/vfx-authoring/scripts/check_gate.py --plan <plan.md>   # 必须 exit 0
```

- `preauthorized` 模式：把用户那句授权原话填进 `--approved-by`，然后直接进 S5（计划仍要落盘，供事后审计）。
- `--approved-by` 必须是原话，不能自批准。契约变了要 `--reopen` 再确认。
- 范围内调参写 `tuning-log.md`（旧值/新值/原因/证据/结论），不扩大授权、不改契约。

## 11. S5 实现与证据

实现细节见 [references/csharp-recipes.md](references/csharp-recipes.md)。

### S5.0 前置

1. 素材复制到 `BangDreamInSpire/BangDreamInSpire/images/vfx/<特效名>/`，语义化命名。
2. `--headless --import` 生成 `.import` 与 uid，**不要手写 uid**。
   改过 `images/**` 里的任何 PNG 之后**必须重跑一次**再 build，否则 pck 里仍是旧 `.ctex`：
   `GODOT=$(dotnet msbuild BangDreamInSpire/BangDreamInSpire.csproj -getProperty:GodotExe)`
   `"$GODOT" --headless --path BangDreamInSpire --import`。
   `stage.sh --no-build` 只跳过 C# 构建，**不跳过贴图导入**——这是"改了图却渲染出旧图"的唯一原因。
3. 场景里按**从底到顶**摆节点，每层 `scale` 按 384px 参考框归一。
4. 基类默认 `Node2D`；只有"飞过去且命中驱动玩法结算"才 `NBangDreamFlyingVfx`。

### S5.1 逐层验证（保留，但一条命令）

**一次写完所有层再录帧是禁止的**——瑕疵无法归因。但每轮不该是手工四步：

```bash
bash .agents/skills/vfx-authoring/scripts/stage.sh \
  -s "res://BangDreamInSpire/scenes/vfx/<场景>.tscn" -n 90 \
  --compare <上一轮 stage 目录>
```

它做 build → 录帧 → 裁中心 → 3×3 关键帧拼图 → 与上一轮逐帧比对。你只需：加一层的代码 → 跑一条命令 → 看 `sheet.png`（整段节奏）和 `compare.png`（本轮新增了什么）。

每轮看三件事：

- 该层出现/消失时刻是否与计划的 `t0`/`t1` 一致；
- 轮廓是否与 S2.5 预演一致（引擎图为准，这一步能立刻看出素材形状缺陷）；
- 加法混合下与已有层叠加是否过曝、是否出现新伪影。

**不通过就停在这一层修，绝不带着已知瑕疵往上叠。** 每轮目录保留，末轮横向对比可判断现象是层内还是层间交互。

只有 1–2 层的简单特效可跳过逐层，但仍必须先单录第 1 层。

### S5.2 全量核对

1. `dotnet build` 通过。
2. 录完整循环（≥2 个 `LIFE`）：`record.sh -s ... -n 130 --gif`
3. 机器校验：`python .agents/skills/vfx-authoring/scripts/verify_frames.py <rec> --fps 60`（一次性效果加 `--fail-on-freeze`；持续/循环效果按预期判断，不机械要求淡出）
4. **1:1 原始像素**目视关键帧（峰值 / 各层消失时刻 / 尾段）——缩放图会掩盖细节。
5. **按正常速度看完整播放**，判断主次、方向、峰值、收尾。不能播放时明确"动态验收未完成"，不从截图宣布通过。
6. 逐条核对验收标准与授权包络，记实际秒数与最终参数。

**编译通过 ≠ 完成。** 已知能骗过编译与无头运行的坑：alpha 曲线写反、粒子朝向差 π/2、ADD + 紫 modulate 偏红、辉光层不跟帧消失——全部只有录帧能看见（见 `docs/vfx-authoring.md` §5.1）。

### S5.3 接入与交付

1. **搜类名与场景路径确认真的接入了**；只命中定义文件即孤儿。`WithHitFx` 解析的是本体资源，改字符串到不了 mod（`docs/vfx-authoring.md` §2.1）。未接入时在计划与交付说明里明确声明。
2. 交付物：场景 + 脚本 +（**仅非本体素材**）贴图与 `.import` + `tuning-log.md`（有调参时）+ mp4/gif。
3. **交付时内联 mp4 与 gif**，不要只给文件名；一句话总结实际观感与验收结论。
4. 特效目录**不产出** `README.md` / `SOURCES.md`；来源凭据写在计划文件里。

## 12. 反模式

只列**脚本兜不住、必须靠判断**的：

- ❌ 把"用户给了明确指令"当成需要访谈，退化成十几轮请示
- ❌ 提案做成同一方案的三个亮度变体（那不是提案）
- ❌ 为了保险选最平庸的方案——合规由脚本保证，创意不该自我审查
- ❌ 一次写完所有层再录（瑕疵无法归因）
- ❌ 带着已知瑕疵往上叠
- ❌ 只用联络表/文件名下最终结论（分辨率与名字都会骗人）
- ❌ 换素材、改主体形态、超包络调参却不重新确认
- ❌ 交付出不了图（mp4/gif 没内联，或只有文件名）
- ❌ 只跑通代码就宣布完成

已被脚本硬门禁覆盖、不必在正文里重复的：未过闸门就写正式资源（`check_gate.py`）、漏 `--approved-by`（同）、跳过归属校验（`check_asset_origin.py`）、`verify_frames.py` 未跑。

## 13. 交付前检查清单

**计划阶段**
- [ ] 候选有真实 uuid / 路径凭据，图片已内联给用户看过
- [ ] S2.5 风险触发项已核对（洞 / 深色描边 / 放大倍数），预演图进摘要
- [ ] 契约块四节齐全；包络写宽到能覆盖预期调参
- [ ] `check_gate.py --plan` exit 0，`approved_by` 是用户原话（或 preauthorized 的授权原话）

**实现阶段**
- [ ] `dotnet build` 通过，无头运行无 error
- [ ] 逐层：每层都有 stage.sh 录制与 `sheet.png`/`compare.png` 目视记录
