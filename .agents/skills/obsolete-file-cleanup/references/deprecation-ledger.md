# 废弃账本：`DEPRECATED.md` 的格式与用法

## 为什么要有账本

`docs/card-authoring.md:197` 规定：**不直接删除仍可能复用的卡图**，改为记账。原因是卡图常被重命名复用、被新卡借用、或被美术重做后需要对照，直接删会丢掉对照依据。

账本位置：`ItsCrychic/ItsCrychic/images/card_portraits/DEPRECATED.md`（该文件当前**不存在**，首次需要时创建）。

## 什么时候记

- 卡被删除或改名，但卡图仍留在仓库里 → 记账。
- 图还在但暂时无对应类（如 `DejaVu.png`、`HachimanguseiDance.png`、`SoIGaveUpOnMusic.png`）→ 记账。
- 图与类都删了 → **不记账**，直接删（属于可删档），但在交付清单里说明。

## 格式

```markdown
# 废弃卡图账本

记录已无对应卡类、但暂不删除的卡图。新增条目按时间倒序追加。

| 文件 | 原属 | 废弃日期 | 废弃原因 | 是否可删 | 替代者 | 证据 |
|---|---|---|---|---|---|---|
| `DejaVu.png` | 无对应类（历史遗留） | 2026-10-19 | 全仓无字面/uid/约定引用 | 待美术确认 | 无 | `scan_orphans.py` confirmed_orphan |
| `HachimanguseiDance.png` | 无对应类（历史遗留） | 2026-10-19 | 同上 | 待美术确认 | 无 | 同上 |
| `SoIGaveUpOnMusic.png` | 无对应类（历史遗留） | 2026-10-19 | 同上 | 待美术确认 | 无 | 同上 |
```

字段口径：

| 字段 | 填写要求 |
|---|---|
| 文件 | 相对 `images/card_portraits/` 的文件名；不写绝对路径 |
| 原属 | 原卡类名；若从来没有对应类就写「无对应类」。**不得虚构** |
| 废弃日期 | `YYYY-MM-DD` |
| 废弃原因 | 一句话，能被复核（如「全仓无引用」「卡被删除」） |
| 是否可删 | `待美术确认` / `可删` / `保留备用` |
| 替代者 | 新图文件名或 `无` |
| 证据 | 产生该结论的脚本与快照名（如 `scan_orphans.py` 的 `confirmed_orphan`，或某次提交 hash） |

## 记录时的硬性要求

1. **资源不存在就写「无对应资源」**，不要为了凑表格编造文件名（`docs/card-authoring.md` 明确禁止虚构）。
2. **证据要可复现**：写清是哪个脚本、哪次运行、哪个快照文件得出的结论。
3. **账本本身也要清理**：条目转为「可删」并实际删除后，把该行从账本移除，同时在提交信息里说明。
4. **账本不替代引用图**：记账是「已知无引用但保留」的登记，不是判定手段。
